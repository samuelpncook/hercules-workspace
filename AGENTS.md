## Architecture rule: web artifacts NEVER call the gateway (engine, 2026-10-10)
- The Secure Vault injects the gateway credential ONLY into the agent's own runtime requests (exec via the dynamic_credentials surrogate). A browser page's fetch() never carries it, and the engine will not mint a browser-exposed token. CORS fixes don't help — the page simply has nothing valid to send.
- Therefore: every web artifact is local-first. The artifact NEVER calls the gateway from page JS or its backend — no token, no Authorization header, no gateway URL in page source or backend code.
- All gateway I/O runs in the agent's runtime: sync-in = agent GETs /tasks → pushes into the artifact via its import action; sync-out = artifact writes user mutations to a local outbox table (+ agent-facing listoutbox/ackoutbox actions), and an agent cron drains it (POST /task-status per op, then ack). The page talks only to the artifact's local actions; taps feel instant and never wait on the gateway.
